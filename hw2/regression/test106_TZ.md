# ТЗ: поддержка pattern-параметров функций (test106)

## Цель
Обеспечить корректное выполнение `hw2/regression/test106.lama` и совпадение вывода с `hw2/regression/orig/test106.log`:
- печатается приглашение `> ` из-за `read()`
- затем строки `1` и `2`

## Контекст теста
Файл `hw2/regression/test106.lama` содержит:
- `fun f (_) { write(1) }` — параметр `(_)` это wildcard-паттерн, принимает любой аргумент.
- `fun g (h : tl) { write(h) }` — параметр `h : tl` матчит непустой список (`Cons(h, tl)`).
- вызов `g({2, 3})` должен привести к `h = 2`, `tl = {3}`, затем `write(h)` печатает `2`.

## Объём работ (минимум для прохождения test106)

### 1) Синтаксис: паттерны в списке параметров `fun`
Разрешить в определениях функций и лямбдах параметры не только идентификаторы, но и паттерны.

Минимальная грамматика:
- `fun <name>? '(' <param> (',' <param>)* ')' '{' <body> '}'`
- `<param> ::= <pattern>`
- `<pattern> ::= '_' | <ident> | <pattern> ':' <pattern> | '(' <pattern> ')'`
  - `:` в паттернах — правоассоциативный (как сейчас в `case`-паттернах).

### 2) Семантика вызова: pattern-matching аргументов
При вызове пользовательской функции:
1. Проверить арность (кол-во аргументов == кол-ву паттернов).
2. Для каждого аргумента выполнить `pattern.match(arg)`:
   - если паттерн не матчится → runtime error (достаточно общего `RuntimeException`).
   - если матчится → получить bindings `Map<String,Object>`.
3. Слить bindings всех параметров в одну карту:
   - если одно имя встречается дважды и значения различаются → runtime error.
4. Создать новый scope (env) для вызова, объявить в нём все bindings как переменные.
5. Выполнить тело функции в этом scope и вернуть результат.

Требования для `test106`:
- Wildcard `_` в параметрах должен давать пустые bindings и всегда матчиться.
- Паттерн `h : tl` должен матчиться на списки, представленные как `Cons(h, tl)` (sexp/tag `"Cons"`), и не матчиться на `Nil`/пустой список `{}`.

## Критерии приёмки
- `mvn -q -Dtest=com.oracle.truffle.lama.test.LamaRegressionTest#runRegressionSuite test` проходит `test106`.
- Вывод `test106` строго равен `hw2/regression/orig/test106.log`:
  - начинается с `> `
  - затем `1` на новой строке
  - затем `2` на новой строке

## Быстрые sanity-checks (опционально)
- `fun f(_) {1}; f(123);` — не падает.
- `fun g(h:tl){h}; g({});` — падает (pattern mismatch).
- `fun g(h:tl){h}; g({2,3});` — возвращает/печатает `2`.
